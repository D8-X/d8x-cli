# Infrastructure Repo

The CLI stores all deployment configs in a GitHub repo. The only requirement to start is the shared Terraform configs and a `config.json` per environment. Everything else is generated by the CLI.

## Creating your own infra repo

1. Create a GitHub repo
2. Add the shared Terraform configs:

```
terraform/
  linode/
    main.tf
    vars.tf
    output.tf
  aws/
    main.tf
    vars.tf
    output.tf
    sg.tf
    routes.tf
    swarm/
      main.tf
      vars.tf
      output.tf
      pg.tf
      routes.tf
```

3. Set `INFRA_REPO=your-org/your-repo` in `.env` or Bitwarden
4. Run `d8x setup new-env` — the CLI creates everything else

## What `new-env` creates

```
my-environment/
  config.json             # chain ID and provider
  terraform.tfvars        # server specs (region, workers, sizes)
  nginx.conf              # main nginx config
  sites.conf              # server blocks for all services
  broker-nginx.conf       # broker server block
  auth_check.conf         # origin/API key whitelist
  staging_origins.map     # empty, managed by CLI
```

## What the CLI adds during deployment

```
my-environment/
  hosts.cfg               # added by: d8x setup provision
  staging_origins.map     # updated by: d8x setup staging-origins
```

## Full repo structure example

```
terraform/                # shared across all environments
  linode/
    main.tf
    vars.tf
    output.tf
  aws/
    ...
testnet/                  # one folder per environment
  config.json
  terraform.tfvars
  hosts.cfg
  nginx.conf
  sites.conf
  broker-nginx.conf
  auth_check.conf
  staging_origins.map
mainnet/
  config.json
  terraform.tfvars
  hosts.cfg
  nginx.conf
  sites.conf
  broker-nginx.conf
  auth_check.conf
  staging_origins.map
```

## GitHub token permissions

The `GITHUB_TOKEN` needs `Contents: Read and write` permission on the infra repo (fine-grained token scoped to the repo).
